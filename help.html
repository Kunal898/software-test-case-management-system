About STCMS

The Software Test Case Management System (STCMS) is a web-based application designed for QA teams to manage their testing workflow. It provides a comprehensive suite of tools for creating and managing projects, test cases, test suites, bug tracking, and generating testing reports.

This application was developed as an academic project for Software Engineering and Quality Assurance (SEQA). It uses HTML5, CSS3, JavaScript (ES6+), Bootstrap 5, Chart.js, and LocalStorage for data persistence.

Quick Start Guide
  1. Login with demo credentials (admin/admin123, tester/tester123, developer/developer123)
  2. Create a Project – Go to Projects and add a new software project
  3. Create Test Cases – Navigate to Test Cases and add test cases for your project
  4. Create Test Suites – Group related test cases into suites
  5. Execute Tests – Go to Test Execution, select a test case, and record results
  6. Report Bugs – When a test fails, report bugs directly from the execution page
  7. Track Progress – Use the Dashboard and Reports to monitor testing progress
  8. Manage RTM – Map requirements to test cases in the RTM section

Frequently Asked Questions
Where is the data stored?
All data is stored in your browser's LocalStorage. Data persists across browser refreshes but is specific to the browser and device you're using. It is not synced across devices.
How do I backup my data?
Go to Settings and click "Export All Data (JSON)". This downloads a complete backup file. You can restore it later using the "Import Data" option.
Can I report a bug from a failed test?
Yes! When you execute a test case and mark it as "Failed", a "Report Bug" button appears. Clicking it will pre-fill the bug report form with details from the test case.
How do I export reports?
Each report page has CSV export buttons. You can also export all data as JSON from the Settings page. The Reports page also has a Print button for physical copies.
Is this application secure for production use?
No. This application uses client-side LocalStorage for authentication, which is NOT secure for production. It is designed for academic demonstration purposes only. Real applications should use server-side authentication, encrypted passwords, and proper session management.
What is the RTM module?
RTM stands for Requirement Traceability Matrix. It maps software requirements to their corresponding test cases, helping ensure complete test coverage. You can add requirements, link test cases, and track which requirements are covered, partially covered, or not tested.
How are quality metrics calculated?
Quality metrics are calculated dynamically from data: Pass Rate = Passed / Executed × 100, Test Coverage = Executed / Total × 100, Defect Density = Total Bugs / Total Test Cases. All formulas update automatically as data changes.
